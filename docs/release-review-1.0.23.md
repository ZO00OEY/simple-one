# 1.0.23 发布前审查

本轮以单人笔记库、多设备同步和用户主动公开分享为使用场景。对上一版备份之后的修复做独立复核，并优先审查笔记写入、剪贴板异步操作、设置渲染、同步调用、分享输出和发布隐私边界。

## 已确认并处理的问题

| 问题 | 触发方式与影响 | 处理 |
| --- | --- | --- |
| 日记自动补写可能覆盖新编辑 | 手动补写读取日记后，还需异步读取前一篇日记；期间用户编辑当前日记，原先的直接写回会覆盖新内容。 | 改用 `vault.process`，仅在当前内容与原始快照一致时写入；否则保留编辑并提示重试。 |
| HTML 剪贴可能删除过期位置 | 等待剪贴板权限或写入期间修改笔记，原先仍按旧位置删除 HTML。 | 剪贴板成功后复核文档；内容变化时只复制、不删除；复制失败也不删除。 |
| 设置改版留下无调用代码 | 旧开关、粘贴选项、锁定输入等渲染方法已无调用，但仍留在源码及样式中。 | 删除 7 个旧渲染方法、相关未用参数和导入，以及 24 条无引用样式规则；启用 TypeScript 未使用代码检查。 |
| 构建检查未覆盖全部新增检查脚本 | 日记开关、正文规则和显示替换的检查没有全部进入默认测试链。 | 纳入 `npm test`，增加本轮两处异步写入回归场景。 |
| 窗口与 API 兼容性细节 | 拖拽计时器未绑定所属窗口；部分标题使用手工 HTML；存在弃用按钮 API。 | 使用所属窗口创建及清理计时器，统一设置标题组件，保持最低 Obsidian 版本兼容。 |

## 验证方法

- 运行 `npm run check`：生产依赖安全审计、ESLint/CSS、完整测试和生产构建。
- 新增用例验证“计算或剪贴板等待期间继续编辑”时，笔记不会被覆盖或误删。
- 回归检查覆盖同步引导、缓存、文件移动、插件配置隔离、下载恢复、冲突和分享发布、阅读器等路径。
- 独立 Agent 复核本轮代码变更、删除方法的调用残留及同步参数移位；另行检查隐私与发行边界。
- 推送前核对实际提交文件，最终 Release 附件仅采用 `main.js`、`manifest.json`、`styles.css`。

## 隐私边界

私人设置、凭据、同步状态、恢复副本、分享清单和自定义模板不进入独立公开源码仓库或 Release。个人文件保留在本机。公开分享会处理 YAML 和隐藏注释、限制配置目录附件，但不对正文和普通外部链接做全量脱敏，发布者仍需审阅内容。

## 限制

这是有重点的代码审查与自动化回归，不是对全部源码的形式化验证。未执行真实远端破坏性同步、批量附件删除或用户私人分享发布。移动端触控、真实剪贴板授权、多窗口及第三方主题的视觉效果仍需实机确认；没有宣称所有网站规则均可长期抓取成功。此前的 `backup/pre-bugfix-2026-10-27` 标签继续保留，便于比较和回退。
